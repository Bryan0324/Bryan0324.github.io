# S9｜程式碼片段解讀

## 短提示卡

```txt
請先解讀我貼的程式，不直接改寫。我懂C位元運算；陌生語法用一句白話說明，重點放在變數角色、控制流程、資料怎麼變。
只依片段與已提供宣告，分清可確定行為、推測意圖、缺少的上下文。說明誰呼叫、何時執行、輸入/回傳/副作用，依執行順序分塊；追一筆小輸入的關鍵值。有跨次狀態再追第二次。注意指標借用/複製、單位/邊界、提前return、callback與非同步完成。
未知API不猜內部行為；越界或未定義行為後不推確定結果。不能只憑名稱/註解判斷有bug，也不假稱已執行。
只給：①一句話用途 ②關鍵變數與分塊解釋 ③簡短追蹤 ④最關鍵缺漏。先解釋能確定的部分，不一次索取整個專案。

語言／平台：
我想看懂的部分／問題：
程式片段（含宣告）：
呼叫端／API定義（沒有就寫未知）：
可用的範例輸入：
解釋深度：分塊／逐行
```

## 工作契約

預設是「幫我建立這段程式的理解」，不是立刻寫新版本。先回答看得出來的內容，缺上下文時只補問會改變解讀的關鍵資訊。
使用者已懂 C 位元運算，不重教每個 AND／shift；遇到 Python、C++ 或框架語法，簡短說清它在本段的作用。
解釋的是程式實際行為；函式名字與註解代表作者意圖線索，不能當作規格證明。

## 第一步：找入口與資料契約

| 要看什麼 | 要回答的問題 |
|---|---|
| 片段角色 | 只是定義函式，還是已被呼叫？初始化、callback、worker、IRQ 各在何時執行？ |
| 輸入 | 參數型別、長度／容量、單位、合法值；有無讀到全域或物件狀態？ |
| 輸出 | return、寫入指標指向的資料、修改物件、publish、log 分別是什麼？ |
| 狀態 | 區域、static、全域、實例屬性或可變預設值；下次呼叫是否仍存在？ |
| 邊界 | 呼叫端、巨集、型別或 API 定義哪些已知，哪些仍未知？ |

`return`、`print`、`publish` 並不等價；`create_subscription` 也不表示 callback 已經執行。
若有原始行號就沿用；沒有時可用「區塊 A/B」定位，不把自編行號說成真實檔案行號。

## 第二步：沿執行順序分塊

1. 初始化哪些值，是否每次執行都會初始化？
2. 哪個條件決定進入哪條路；哪些路徑會提前 return？
3. 迴圈的起點、條件、更新，會存取哪些索引？`break` 跳出哪層、`continue` 跳過哪些工作？
4. 每個關鍵呼叫收到什麼、回傳值如何使用、是否有輸出參數或其他副作用？
5. 結束前結果如何交給外部；是否仍有背景工作使用目前資料？

逐行解釋只在使用者需要時做，不將每行翻譯成中文卻漏掉整體資料流。

## 第三步：追一筆資料

用短表：`步驟／條件｜關鍵值之前→之後｜讀寫位置／輸出`。只記影響結果的變數。

```c
uint32_t sum_tail(const uint32_t *data, size_t n) {
    uint32_t sum = 0;
    for (size_t i = 1; i < n; ++i) {
        sum += data[i];
    }
    return sum;
}
```

假設 `data` 指向至少 n 個有效元素。對 `[7,2,4]`、n=3：

| 步驟 | i | sum | 意義 |
|---|---|---|---|
| 初始化 | 尚未進迴圈 | 0 | 本次呼叫的區域累積值 |
| 第一次 | 1 | 0→2 | 讀 data[1] |
| 第二次 | 2 | 2→6 | 讀 data[2] |
| 判斷／返回 | 3，不小於 n | 6 | 回傳 6 |

可確定：它忽略 data[0]，回傳其餘元素的 uint32 累加，不改輸入；n=0 或 1 時不進迴圈，回傳 0。數值超出 uint32 範圍時按無號規則取模。
**不能只因未加 data[0] 就說它有 bug**：可能首元素是標頭。只有題目要求「所有元素總和」時，才能據此判定不符需求。

## 容易被解讀錯的地方

- `p = q` 通常是指標／參考的複製，不等於複製所指資料；`const` 也不保證其他執行者不會改底層 buffer。
- Python `b = a` 共用物件；slice 或容器複製是否足夠，還要看裡面是否有可變物件。
- `sizeof(pointer)` 不是配置容量；函式參數的長度需要看介面契約。
- `queue_submit(buffer, count)` 僅憑名稱不能知道是否深複製、是否同步、count 單位或返回碼語意。應索取宣告與契約／實作。
- C signed overflow、無效 shift、越界、懸空指標等不能用「一般會得到某值」代替語言規則。追蹤到第一個問題就標出推導界線。

1. 一句話概述目前行為。
2. 關鍵變數、輸入／輸出與副作用。
3. 分塊解釋＋一筆追蹤；有跨次狀態再追第二次。
4. 可確定／有條件／未知，最後只問最關鍵缺漏。
