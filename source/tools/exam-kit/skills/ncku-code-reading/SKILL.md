# S9｜程式碼片段解讀

## 工作契約

- 預設任務是解釋目前程式，不直接改寫。依使用者指定的語言、版本、片段與宣告作答。
- 使用者熟悉 C 位元運算；優先解釋變數角色、資料流、呼叫與執行時機。陌生語法用一句白話補足。
- 區分「片段可確定的行為」「可能意圖」「待補上下文」。名稱、註解與函式宣告不足以證明外部 API 會複製資料、同步完成或接管所有權。
- 不要求取得整個專案才能開始；先解釋確定部分，再問目前最關鍵的一項。考場由人提供內容、執行與回報，不假稱已讀取或跑過未提供的資料。

## 步驟

1. 定位這段是宣告、初始化、一般函式、callback、主迴圈或中斷處理；指出誰呼叫與何時執行，未知就標未知。
2. 摘出輸入、回傳、輸出參數與副作用；列關鍵變數的型別、單位、有效範圍與生命週期。
3. 沿真正執行順序分塊說明，涵蓋分支、迴圈邊界、return／break／continue、錯誤與提前退出路徑。使用者要求逐行時才逐行展開。
4. 追蹤一筆小輸入的關鍵值；涉及全域、static 或可變預設參數時，再追第二次呼叫。沒有合法輸入範圍就先說明推導前提。
5. 說清楚讀哪裡、寫哪裡、是否別名／借用、是否改原輸入，以及呼叫返回是否表示工作完成。遇到缺少定義的 API 就停在邊界，不編造內部行為。
6. C/C++ 遇到越界、未定義行為或未知初始化時，不給確定數值；標出首次無法可靠推導的位置。只有行為與需求已知不符時，才標為缺陷並轉 S10。

## 固定輸出

1. 一句話概述目前可確定的行為。
2. 輸入／輸出／關鍵變數與副作用，僅列相關項目。
3. 分塊執行順序與一筆簡短追蹤。
4. 假設與缺漏，以及接下來最值得補的一項資料。

需要修錯時轉 `ncku-debug-analysis`；領域細節再依證據選 ROS／PIO／併發／DMA 技能。詳細知識卡、案例與可貼入聊天的短卡見同目錄 `index.md`。
