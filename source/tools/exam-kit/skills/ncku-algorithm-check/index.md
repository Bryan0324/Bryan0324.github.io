# S7｜正確性、序列化與演算法移植

## 短提示卡

```txt
依題目精確規格，把問題切成解包→純運算→打包。先固定一筆失敗輸入與ID，確認兩端數值/bytes相同，再查算法。命令由我執行，不假造judge結果。
struct可能有padding，ROS物件不等於指定wire bytes；確認欄位順序、byte order、長度與NUL。CRC先確認poly/init/refin/refout/xorout，不預設zlib符合。SHA-1為20 bytes而非40字元hex。排序先查同值規則、比較器與平方和溢位；先升型再運算。只有高速連發錯，先查buffer重用/ID/競態。
只給：①第一個差異層或必要缺漏 ②最小修正 ③獨立已知向量/參考與邊界驗收。不整份重寫。
```

## 工作契約

依題目精確規格驗證，不把同名演算法的不同變體混為一談；不預設今年題目沿用歷屆 MNIST/SHA/CRC。
保留介面、ID 與可改範圍。沒有執行環境時提供可跑的主機驗證方法，不假裝執行 judge。
需求未知時先索取會改變答案的規格，不以自訂答案規則讓測試「通過」。

## 執行步驟

1. 把需求寫成 input → output 契約：型別、範圍、長度、順序、錯誤處理、ID、同值規則。
2. 固定一筆最小失敗案例，保存原始輸入與實際輸出，避免隨機輸入持續改變問題。
3. 分離三層：message／bytes 解包→純運算函式→結果打包／publish。
4. 先比對兩端是否看到同一筆數值／byte stream，再檢查演算法；hash 全錯常是輸入格式不同。
5. 建立獨立參考：已知測試向量、可信標準庫、簡單易懂的主機實作；不要把待測程式翻譯一次就當獨立 oracle。
6. 測正常、零／空（規格允許時）、重複、負值、最大邊界；再跑連續輸入檢查 ID／生命週期。

## 序列化知識卡

- 記憶體 struct 可能有 padding；不能假設 `sizeof(struct)` 等於 wire 格式長度。
- 每個欄位按規格明確寫入 bytes；確認 little/big-endian、signed int 的表示、欄位順序與陣列個數。
- 二進位資料不能用 strlen 決定長度，遇 0 byte 會截斷；是否包含字串末尾 NUL 由規格決定。
- ROS message 物件、DDS 序列化內容、題目指定的演算法輸入 bytes 是三個不同層次。
- callback 借用的 buffer 在回傳後可能被重用；只在高發送率錯時，優先查所有權與 ID，再去改演算法。

## 排序／數值知識卡

- comparator 應給負／零／正，直接 `return a-b` 可能溢位；可用比較結果構成符號。
- 先升型再乘：`(int64_t)x * x`，不是計算完再 cast。
- 若三個座標允許完整 int32 範圍，三個平方和可能超過 signed int64；每個平方可用 int64 算，再以 uint64 合計。若題目範圍更小可採更簡單方案。
- 用平方距離取代 sqrt 只有在符合題目比較語意／精度／同值規則時才成立。
- 若需要穩定排序或 tie-break，明確實作，不自行選擇字典序取代題意。
- C signed overflow 不應當成固定寬度 wrap；CRC 等 bit 運算通常使用明確 unsigned 型別。

## Hash／CRC 知識卡

- SHA-1 digest 為20 bytes；40個十六進位字元是顯示格式，不是相同輸出型別。
- CRC 至少確認 width、poly、init、refin、refout、xorout。硬體 sniffer 的 bit reverse/byte swap/invert 不可憑演算法名稱推定。
- 標準 CRC-32/ISO-HDLC 對 ASCII `123456789` 的 check 值是 `0xCBF43926`；只有變體一致時才可拿來驗收。
- `zlib.crc32` 可作這個標準 CRC-32 的主機參考，不代表適用所有 CRC 題。
- 先驗證每包是否重新初始化 accumulator，再查跨包狀態殘留。

## 移植流程

先讓純函式在主機通過最小向量，再接回 callback。保留原演算法必要的資料型別、表格與初始化。
若硬體記憶體受限，先量 stack/static buffer 與輸入長度，不用刪資料／截斷輸入來降低用量。
只看得分失敗摘要無法定位時，要求一筆可見測例的 input/output、或按規格建立自己的參考案例。

## 微型驗證

若 wire 格式明訂三個 little-endian int32，數值 `(1,-2,3)` 應是12 bytes：
`01 00 00 00 FE FF FF FF 03 00 00 00`。
只有兩端 byte stream 一樣，才值得比較 CRC/SHA 的計算本體。

## 固定輸出

1. **契約＋第一個差異所在層**。
2. **最小失敗案例與預期值來源**。
3. **最小修正／純函式實作**，不動無關通訊層。
4. **驗證清單**：已知向量、邊界、端到端 ID；如果只在併發失敗，交 S5/S6。
