# 短提示卡總索引

S0～S10 的短卡在各技能頁首，詳解在同頁下方。**只複製「短提示卡」文字區塊＋填妥的本題資料**；X1 與交接卡在本頁。操作方式見 [聊天指南](../chat-workflow)。

| 卡片 | 遇到的問題 |
|---|---|
| [S0 讀題](../skills/ncku-exam-triage/#短提示卡) | 拆解規格、可改範圍、下一個小任務 |
| [S1 建置](../skills/ncku-build-debug/#短提示卡) | 環境、編譯、連結、燒錄 |
| [S2 ROS](../skills/ncku-ros-dataflow/#短提示卡) | topic、message、QoS、callback |
| [S3 ISA](../skills/ncku-isa-binary/#短提示卡) | 指令格式、立即數、PC、byte order |
| [S4 PIO](../skills/ncku-pio-state-machine/#短提示卡) | shift、FIFO、狀態機、CPU 設定 |
| [S5 併發](../skills/ncku-concurrency/#短提示卡) | 共享資料、鎖、競態、生命週期 |
| [S6 DMA](../skills/ncku-transfer-dma/#短提示卡) | 搬運單位、increment、DREQ、完成 |
| [S7 正確性](../skills/ncku-algorithm-check/#短提示卡) | 演算法、序列化、最小反例 |
| [S8 效能](../skills/ncku-performance/#短提示卡) | 得分門檻、基準、有效吞吐 |
| [S9 程式解讀](../skills/ncku-code-reading/#短提示卡) | 看懂片段、變數、分支、資料變化與副作用 |
| [S10 分析 Debug](../skills/ncku-debug-analysis/#短提示卡) | 錯誤重現、第一個偏離點、診斷實驗、修正與回歸 |
| [X1 創意發想](#創意發想) | 比較最多三個有條件的替代方案 |
| [交接模板](#交接模板) | 重開對話、保存已驗證事實 |

不知道程式在做什麼→S9；知道預期但實際不符、還沒定位原因→S10。工具／建置失敗用 S1，已確定是算法或序列化錯用 S7。

## 交接模板

```txt
繼續處理這一個小任務。以下由我核對過；缺資料先問，不把推測當事實。命令由我執行。
目標／成功條件：
平台／版本／工具：
可改檔案／函式／限制：
必要API／message／單位規則：
目前版本的相關程式（本輪附上或尚缺）：
已驗證事實（指令→觀察）：
已試且無效的修改：
最新輸入／預期／實際錯誤：
本輪只要：
請給一個最小修改或檢查，附預期結果。不重寫整個專案，不假稱已測試。
```

## 創意發想

```txt
X1｜有約束的創意發想
請用我提供的規格找替代解法；命令與驗證由我執行。先找可改變的決策，例如資料表示、計算順序、工作分工、預計算或搬運/計算重疊，不要只把同一方案換名字。
提出最多3個機制不同且符合可改範圍的方案；不夠就少提。每案只寫：核心方法｜成立前提/所需資源｜收益機制｜可能失敗點｜最小驗證與預期觀察。
未知硬體能力/API須標待查並指出查什麼，不發明PIO指令、DMA功能或加速數字。若是除錯，先給能區分原因的實驗，不因猜測重寫；若是效能，先確認正確率門檻與基準。
最後推薦一個現在最值得驗證的方案並說理由。先不產生完整程式，等我選定再拆成一個小任務；解釋保持精簡。

目標：解法設計／卡關替代／效能改良
需求、成功條件、不可改的限制：
平台／已確認API／CPU、PIO、DMA、RAM等可用資源：
現有方法、已驗證事實／基準數據：
已試過但無效的方法：
可改範圍、剩餘時間、希望改善的指標：
```
