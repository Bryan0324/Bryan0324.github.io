# 考場網頁聊天：短提示卡操作法

依[最新公告](exam-rules)：模型名稱不公開，只有網頁聊天、不能上傳檔案，單次貼文與對話長度有限；實際上限未知。

**預設用短卡，不貼完整skill。** 每張短卡都自帶必要規則與填空資料包；完整skill用來查閱、補充某一段必要規則。
短卡長度是本包的編寫選擇，不代表考場字數/token上限，也不保證一次能貼多少程式碼。

## 1. 看到什麼，開哪張卡

| 現象 | 短卡入口（同頁下方有詳解） |
|---|---|
| 新題／不知從哪開始 | [S0](skills/ncku-exam-triage/#短提示卡) |
| 看不懂程式碼片段／想逐步追值 | [S9 程式解讀](skills/ncku-code-reading/#短提示卡) |
| 結果錯／例外／卡住，尚不知哪一層有問題 | [S10 分析 Debug](skills/ncku-debug-analysis/#短提示卡) |
| 工具／import／編譯／燒錄錯 | [S1](skills/ncku-build-debug/#短提示卡) |
| ROS沒資料／補callback | [S2](skills/ncku-ros-dataflow/#短提示卡) |
| ISA／立即數／欄位格式 | [S3](skills/ncku-isa-binary/#短提示卡) |
| PIO／FIFO／bit順序 | [S4](skills/ncku-pio-state-machine/#短提示卡) |
| 偶發錯／共享狀態／死鎖 | [S5](skills/ncku-concurrency/#短提示卡) |
| DMA／搬錯／卡busy | [S6](skills/ncku-transfer-dma/#短提示卡) |
| 資料有到但答案錯 | [S7](skills/ncku-algorithm-check/#短提示卡) |
| 正確但慢／提速失分 | [S8](skills/ncku-performance/#短提示卡) |
| 想找不同解法／現有設計受限 | [X1 創意發想](prompts/#創意發想)：選定方案後回對應 S 卡 |
| 對話長了／換題／重新開啟 | [交接模板](prompts/#交接模板)：核對事實與最新版本再貼 |

只複製短卡的文字區塊，保留末尾填空；不要一次複製整頁詳解。所有卡片亦可從 [prompts 總索引](prompts/) 找到。

S9 用來看懂目前行為，先不要求改碼；S10 用「預期 vs 實際」定位並修錯。S1 處理工具／建置階段，S7 處理已確定的算法／資料格式。若用 S9 看出可疑處，下一輪補規格與失敗案例再交 S10，不把推測直接當 bug。

## 2. 三輪工作節奏

**第一輪：定位。** 貼一張卡＋本小題的需求/限制＋最相關的程式與錯誤。未知欄位填未知，請模型只指出一個檢查或最小修正。

**第二輪：補證據。** 實際執行，貼「指令、原始輸出、預期差異」。若模型問header，貼需要的宣告與型別；問QoS，就貼相關endpoint。

**第三輪：驗收。** 套一個修改，用固定輸入檢查。記錄修改過的版本與結果。未改善則重新定位，不累積無依據的修法。

同一對話不用每輪重貼短卡；改主題或模型忘記關鍵限制時，才補相關規則或開新對話。

### X1創意發想何時有用

- **設計前**：題意已清楚，想比較不同資料表示、處理順序或工作分工。
- **卡關時**：目前方法受資源或介面限制，想找能滿足同一規格的替代途徑。具體錯誤仍先依證據診斷。
- **優化時**：已有正確基準，想選下一個有理由的實驗，而不是盲目改參數。

例如CPU copy已正確，但只剩512 bytes額外RAM：可比較沿用CPU、使用已確認的DMA、或在規格允許下分塊處理。模型須指出前提與驗證，不能直接要求兩個完整大buffer或保證DMA較快。
有幾個方案就列幾個，不強迫湊滿。你選定一案後，帶規格／API／當前程式交S4/S5/S6/S7/S8實作；需要查硬體能力先用[三大文件導覽](docs-guide)。

## 3. 程式碼超過貼上限制時

先縮小任務，不把整個專案拆成十段塞進同一對話。

| 問題 | 先貼的最小完整關係 | 暫時不必貼 |
|---|---|---|
| 看不懂片段 | 語言、完整函式、相關型別／宣告、呼叫端、想理解的點 | 無關檔案；缺定義的 API 可先標未知 |
| 邏輯／執行錯誤 | 目前版本、最小失敗輸入、預期依據、實際輸出／traceback、相關呼叫順序 | 大量正常日誌；不能省掉跨次狀態所需的前次呼叫 |
| 編譯錯 | 指令、第一個error及上下文、該符號宣告、出錯函式 | 全部build log、無關檔案 |
| ROS callback | message欄位、pub/sub建立碼、callback、必要spin設定 | 整個package、無關節點 |
| PIO | 短PIO程式、shift/FIFO/wrap/enable、CPU收送 | 不相關GPIO或其他周邊設定 |
| race | 共享宣告、各讀寫路徑、鎖/生命週期 | 純計算內部細節可先摘要，但不可省略它的共享副作用 |
| DMA | API宣告、buffer型別/容量、配置/啟動/完成 | 無關DMA channel的業務邏輯 |
| 算法錯 | 規格、單筆失敗輸入、純函式、打包/解包相關段 | 全資料集、其他已正常算法 |

- 每段註明「檔案、函式、此版本的行號範圍」；保留型別、宏、單位、呼叫關係。
- 刪去的部分用文字說明其作用，不能讓模型以為它不存在。
- 若兩段必須合看且合計仍在可用上下文內，可分兩則並先說「第1/2段，請等第2段再診斷」。不要靠大量分段繞過對話長度限制。
- 要求只輸出指定函式或精確替換區塊，附前後定位文字；避免大段diff或整檔重寫造成輸出截斷。

## 4. 對話重開：你保存事實，模型接續小任務

在考場電腦的工作筆記維護[交接模板](prompts/#交接模板)，每個里程碑更新一次。
可以請模型整理候選摘要，但你要對照實際指令、程式與輸出修正；模型說「已修好」不等於測試通過。
新對話帶必要規則與當前小段程式，不帶整段聊天歷史。

## 5. 紙本＋雲端的準備方式

- **紙本**：[列印速查](print-quickstart)、你常忘的ROS/PIO/DMA頁、官方文件網址。可考前自行保存官方重點頁並列印；考場不提供離線文件。
- **雲端筆記**：cheatsheet、短卡、完整skills、參考連結與範例。選能直接開啟、搜尋、複製純文字的頁面，保持相對連結。
- **入口備援**：在紙本寫下入口網址與短路徑；不用依賴手機掃QR或收驗證碼。若雲端登入需個人裝置驗證，考前另備可直接閱讀的靜態筆記入口或足夠紙本。
- **普通網頁查詢**：直接開[官方文件索引](references)。搜尋時用可關閉/避開AI摘要的普通結果，不使用AI摘要、外部LLM或AI編程功能。
- **當天環境**：先看官方啟動指令與既有建置檔。Jazzy Docker與歷屆PlatformIO命令都是參考，不能預設考場必須重建同一套環境。

本次僅本機建置與檢查，未發布到遠端；考前仍須實測正式入口。網頁聊天不是 skill 執行器，這些頁面不會使模型自動讀檔或執行工具。
