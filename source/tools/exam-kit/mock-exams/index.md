# 模擬上機考

這裡是依 exam-kit 題型設計的**原創練習**，不是正式考題、命中預測或歷屆完整重現。

| 試卷 | 時間／滿分 | 環境 | 題型 |
|---|---|---|---|
| [A 卷：資料接收、搬運與驗證](set-a/) | 120 分鐘／100 分 | Python 3.9+、支援 C11 的 C 編譯器 | ROS 診斷、ID／序列化／CRC、C 搬運描述、PIO／buffer、RV32I、效能 |

A 卷的程式題都能在主機驗收，不需要 Docker 或開發板。ROS／PIO 題提供固定診斷資料，按分析與驗證計畫評分，不能把筆試通過當成板端已跑通。

## 用 Iceman Free 測試的方式

1. 由你開新聊天、手動貼題目與相關程式，執行命令並回貼結果；模型只負責提出修改與分析。
2. 每次只貼一道題的規格與必要片段。可搭配 [S0～S10 短卡](../prompts/)，不預設 Iceman Free 的模型大小、貼文上限或工具能力。
3. 計時包含理解、選卡、往返、編譯與驗收。至少重開一次對話，用交接卡繼續。
4. 作答期間先不開參考解答；測試資料與驗收腳本是公開的，可用失敗案例除錯，但不能硬編測例答案。
5. 分開記錄**題目分數**與**協作品質**。若比較「裸問」與「搭配短卡」，用不同的新對話並記錄是否已看過答案；同一題二刷不能當完全獨立測量。

Iceman Free 由你負責實測；本包提供題目與驗收工具，沒有代測或聲稱其能力。考試當天仍依 [公告](../exam-rules.html) 使用考場指定模型。

看不懂模型給的程式，先貼 [S9](../skills/ncku-code-reading/#短提示卡) 請它分塊解讀與追值；驗收失敗但原因不明，貼 [S10](../skills/ncku-debug-analysis/#短提示卡) 加原始輸出定位。兩者都只帶目前那題的必要內容。
