# 用固定案例校準考場模型

目的：先確認「短提示卡＋這個模型＋你的貼法」能否合作。模型名稱依公告不公開；以下是待執行評測卡，尚未在考場模型取得成績。

## 怎麼測

1. 開新對話，只貼對應[短卡](prompts/)與該案例輸入，不先貼完整skill。
2. 不先貼下面的通過標準，避免模型直接照抄答案。
3. 記錄是否通過、花多久、補了幾輪資料。答對術語不夠，要給可執行的下一步。
4. 若模型反覆失敗，針對缺漏從完整skill摘一段規則，再測同類新案例；資料太長則先縮小任務。
5. 考前可用其他模型做模擬；考試期間只能用考場模型。當天用第一個實際小任務觀察其表現即可，不必先花大量時間跑完校準題。

統一評分：每項0或1分，滿分4分。
- 能指出有證據的問題，資料不足時知道缺什麼。
- 沒有發明現場 API、欄位、工具執行結果或題目規則。
- 提出最小修改／一個能區分原因的觀察。
- 有具體驗收方式與預期結果。

## 固定案例

| 案例／技能 | 只貼給模型的資料 | 通過標準（自己看） |
|---|---|---|
| C0／S0 | 新題要求接收自訂 message、回傳同ID的結果；未給.msg與可修改路徑，請直接寫完整韌體 | 先索取介面與可改範圍；可規劃流程，但不假造欄位或平台 |
| C1／S1 | WSL裡 `python3 processor.py` 回 ModuleNotFoundError: rclpy；檔案有ROS import，尚不知是否進container | 先查環境／Python來源；指出需進正確ROS環境，不直接pip安裝或重寫程式 |
| C2／S2 | publisher `/number` Int32；processor訂閱 `/numbers` Int32；兩node存活；`/double`無輸出 | 指認topic差異，修名稱，先開echo再用21→42驗收 |
| C3／S3 | RV32I，PC=0x100，BEQ目標0xFC，問offset與是否先加4 | offset=-4，以當前指令PC為基準，說明B-type重排與alignment |
| C4／S4 | 程式只有out/in/push；CPU設定沒有提供；問為什麼卡住 | 不斷言唯一原因；要求shift/autopull/autopush/FIFO/enable與CPU收送碼，提出可區分的檢查 |
| C5／S5 | 全域sink在鎖外 `sink += work(i)`，counter++在mutex內，結果40000，問是否無race | 指出sink仍race，volatile不是修法；提local累積＋join合併或完整同步 |
| C6／S6 | `engine_claim()`回-1；job複製8個uint32_t，count=32、size=XFER_32 | 同時抓到無效channel與bytes/transfers混淆；不以加大buffer解決 |
| C7／S7 | 題目只說「CRC32」，沒有poly/init/reflection/xorout，模型需給與judge一致的程式 | 明確要求變體或權威測試向量，不保證zlib一定吻合；可給附條件的標準版本 |
| C8／S8 | 門檻95/100；A=100正確/2秒，B=90正確/1秒，問是否採B | 不採B，因未過門檻；量測有效吞吐與錯誤／丟包原因 |
| C9／X1 | 4096個uint32_t的CPU copy已正確；現有src/dst不能更改，額外RAM只剩512 bytes；DMA有無可用channel未知，也沒有耗時數據。請發想更快方案 | 提出少量不同且有前提的方案，不配置兩個完整大buffer、不保證DMA較快；先查資源／量基準，附最小驗證，選定前不產生整套改碼 |

## 輸出太長或失控時的縮短指令

```text
只處理以下一個問題，不要重寫整個專案。
必要規則：[貼skill中直接相關的3～6條]
觀察資料：[真實指令、輸出、程式]
目標：[一個可驗收結果]
請只輸出：
1. 有證據的判斷（最多3句）。
2. 一個最小修改或下一個檢查動作。
3. 我應看到什麼；若沒看到，下一步需要哪份資料。
沒有工具時不要聲稱已執行；沒有定義的API不要自行發明。
```

## 實測紀錄空表

另測兩項操作：貼文被拒絕時，能否保留宣告／呼叫關係而縮小案例；開新對話只貼[交接卡](prompts/#交接模板)與目前小段程式，是否能繼續。記錄當天介面實際限制，不預設固定token或程式碼行數。

|---|---|---|---|---|

只知道模型名稱不夠：不同大小、量化、上下文長度、工具權限都可能改變表現。選一組真實題目做端到端演練，比讓旗艦模型自評「提示詞很強」更有用。
